# Quick Task 260822-01: Kitchen Orders + Combined Settlement Summary

KOT-style send-now/pay-later/settle-once flow: attendants send carts to the kitchen as real UNPAID `pending` orders, then one payment settles the entire tab — every prior order row stamped `settled` with payment_method + razorpay ids — and a single combined receipt lists all items from all orders.

## What Was Built

### Task 1 — `settleOrdersWithPayment` store action (`smartpos-main/lib/store.ts`)
- New interface declaration + zustand implementation mirroring `settleTab`, placed directly after it.
- Bulk-updates all `pending`/`in_progress` rows of restaurant+table+tab to `'settled'`, stamping `payment_method`, `razorpay_order_id`, `razorpay_payment_id` (`|| null`) and `updated_at`.
- On success clears `activeOrders` only — cart clearing is left to the UI receipt flow.
- `settleTab`, `createOrder`, and all other actions byte-identical (verified via git diff).

### Task 2 — Settle mode UI (`CustomerMode.tsx`)
- `settleMode` + `sendingToKitchen` local state; store destructure swapped `settleTab` → `settleOrdersWithPayment`.
- **Send to Kitchen** button inserts an unpaid `'pending'` order via `createOrder` (empty customer fields, empty razorpay ids) then clears cart; toast confirms. Order appears under Previous Orders immediately and is visible to KitchenMode automatically.
- Header **Settle All → Settle Now** toggle (amber when active, "Cancel Settlement" label); the old silent no-payment `settleTab` path is deleted from this component.
- Table/Tab selects route through `handleTableChange`/`handleTabChange` which reset settle mode (QD-05).
- **Place & Pay** gated by `canPay = settleMode && (activeOrders.length > 0 || cart.length > 0)` (QD-08); green styling + `Settle ₹X` label showing combined total while in settle mode; Clear Cart untouched (QD-07).
- Amber settlement banner at CartContent top; PaymentModal amount = `activeOrdersTotal + totalWithTax` (QD-03).

### Task 3 — Combined settlement flow (`handlePaymentSuccess`)
- Snapshots items/tax/subtotal/counters BEFORE any await (render-closure safety).
- Cart non-empty → `createOrder` FIRST with the real payment (failed insert aborts before any settle); cart empty → `receiptId = activeOrders[0].id` (QD-06).
- `settleOrdersWithPayment` stamps every `pending`/`in_progress` row of the tab with shared payment ids.
- Builds a `ReceiptOrder`-compliant combined receipt: merged items from all settled orders + cart extras, summed subtotal/tax/grand total, payment method, cash/change info.
- Success-only cleanup: close payment, show receipt, clear cart, clear customerInfo, exit settle mode; snapshot-based "Settled N order(s)" toast. Email/WhatsApp tail preserved verbatim.

## Deviations from Plan

**1. [Rule 1 - Bug] Shared payment ids for ALL settled rows (Task 3 step 4 vs must_haves/verification conflict)**
- **Found during:** Task 3 implementation review
- **Issue:** Plan step 4 literally passes raw `paymentData.razorpayOrderId/razorpayPaymentId` to `settleOrdersWithPayment`, which would leave prior orders' razorpay ids NULL on cash payments. This contradicts the plan's own must-have truth ("ALL ... become 'settled' WITH payment_method and razorpay ids stamped"), verification step 5 ("all rows settled with payment_method='cash' + cash_ ids"), and threat mitigation T-Q1-02.
- **Fix:** Cash-convention fallback ids (`cash_${Date.now()}` / `cash_payment_${Date.now()}`) computed ONCE before awaits and passed to both the cart-order insert and the settle call, so every row of one payment event carries identical ids.
- **Files modified:** smartpos-main/app/features/customer-mode/CustomerMode.tsx
- **Commit:** b9c8363

**2. [Cosmetic] Email subject uses `receiptId` instead of `order.id`**
- **Found during:** Task 3 rework
- **Issue:** Original subject referenced the just-created order's id; that variable only exists in the cart-non-empty branch now.
- **Fix:** Subject uses `receiptId` so it stays correct when settling prior orders with an empty cart.
- **Files modified:** smartpos-main/app/features/customer-mode/CustomerMode.tsx
- **Commit:** b9c8363
